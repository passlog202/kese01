# 智能导购系统 · 前后端契约 V6

> 目标：抽象一套稳定的 JSON 契约，**前端（Vue 3 + Element Plus）与后端（FastAPI）解耦**。
> 前端通过 HTTP 调用后端契约服务，契约已在 `server/` 下完整落地，
> 同时保留 `api_contract.py` 供进程内直接调用。
>
> HTTP 根路径前缀：`/api/v1`
>
> **认证**：JWT Bearer Token（HS256）；密码使用 PBKDF2-HMAC-SHA256 哈希存储。
> 除「健康 / 注册 / 登录 / 发送验证码 / 校验验证码 / 重置密码」外，其余业务端点均需登录。
> 支持邮箱注册与找回密码：验证码仅存哈希、10 分钟有效、5 次尝试限制。
>
> **安全**：验证码发送限流（邮箱冷却 + 小时/ IP 上限）、登录失败锁定、接口 IP 限流、
> 请求体大小限制、安全响应头。详见 §7。

### 0.2 统一错误结构

所有 4xx/5xx 响应体使用统一结构：

```json
{
  "api_version": "1.0",
  "ok": false,
  "data": null,
  "error": {
    "code": "INVALID_REQUEST",
    "message": "缺少必要字段 budget_max",
    "field": "budget_max"
  }
}
```

错误码：`INVALID_REQUEST`（参数错误）、`NOT_FOUND`（资源不存在）、`INTERNAL_ERROR`（服务器错误）、
`UNAUTHORIZED`（未登录/凭证无效）、`INVALID_CREDENTIALS`（用户名/邮箱或密码错误）、
`USER_EXISTS`（用户名已存在）、`EMAIL_EXISTS`（邮箱已被使用）、
`CODE_INVALID`（验证码错误）、`CODE_EXPIRED`（验证码过期）、`CODE_LOCKED`（尝试次数超限）、
`CAPTCHA_REQUIRED`（缺少图形验证码）、`CAPTCHA_INVALID`（图形验证码错误/过期/已使用）、
`RATE_LIMITED`（限流）、`ACCOUNT_LOCKED`（登录账号锁定）、`PAYLOAD_TOO_LARGE`（请求体过大）。

## 1. 认证接口

### 1.0 统一约定

- 客户端在受保护接口的请求头携带：`Authorization: Bearer <token>`
- token 由注册/登录接口返回，有效期默认 7 天（`KESE_TOKEN_EXPIRE_MINUTES` 可调）。
- 凭证无效时返回 `401` + 错误码 `UNAUTHORIZED`；前端收到 401 会清除本地登录态并跳转登录页。
- **注册与登录强制图形验证码**：先 `GET /api/v1/auth/captcha` 获取 `id` 与图片，随请求提交
  `captcha_id`/`captcha_code`；验证码一次性使用、默认 180 秒过期，错误后需重新获取。

### 1.1 `POST /api/v1/auth/register`（注册）

**请求体 `RegisterRequest`**

```json
{
  "username": "alice",
  "password": "secret123",
  "email": "alice@example.com",
  "captcha_id": "d8eefc3e...",
  "captcha_code": "K7Q2"
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| username | string | 是 | 3~32 位，字母/数字/下划线/中文 |
| password | string | 是 | 6~64 位 |
| email | string | 否 | 合法邮箱格式；不填则不校验邮箱 |
| captcha_id | string | 是 | 由 `GET /auth/captcha` 下发 |
| captcha_code | string | 是 | 图中 4 位（不区分大小写） |

缺少或错误的图形验证码 → 400 + `CAPTCHA_REQUIRED` / `CAPTCHA_INVALID`。

**响应 `AuthResponse`**（用户名已存在 → 409 + `USER_EXISTS`）

```json
{
  "api_version": "1.0",
  "ok": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": { "id": 1, "username": "alice" },
    "token_type": "bearer"
  },
  "error": null
}
```

### 1.2 `POST /api/v1/auth/login`（登录，用户名或邮箱）

**请求体**：`{ "username": "alice 或 alice@example.com", "password": "...", "captcha_id": "...", "captcha_code": "..." }`。
错误密码 → 401 + `INVALID_CREDENTIALS`；缺少/错误图形验证码 → 400 + `CAPTCHA_REQUIRED` / `CAPTCHA_INVALID`。

### 1.3 `GET /api/v1/auth/me`（当前用户，需登录）

```json
{ "api_version": "1.0", "ok": true, "data": { "id": 1, "username": "alice", "email": "alice@example.com" }, "error": null }
```

### 1.4 `POST /api/v1/auth/send-code`（发送邮箱验证码）

**请求体**：`{ "email": "alice@example.com", "purpose": "register | reset" }`

**响应 `SendCodeResponse`**（调试模式会回显 `code`，生产环境 `code` 为 null）

```json
{
  "api_version": "1.0",
  "ok": true,
  "data": { "message": "验证码已发送，请查收", "code": "123456", "debug": true },
  "error": null
}
```

### 1.5 `POST /api/v1/auth/verify-code`（校验验证码）

**请求体**：`{ "email": "...", "code": "123456", "purpose": "register | reset" }`

- 校验通过 → `{ "ok": true, "data": { "verified": true } }`
- 验证码错误 → 400 + `CODE_INVALID`（含剩余次数）
- 已过期 → 400 + `CODE_EXPIRED`
- 尝试次数超限 → 429 + `CODE_LOCKED`

### 1.6 `POST /api/v1/auth/reset-password`（邮箱验证码重置密码）

**请求体**：`{ "email": "...", "code": "123456", "new_password": "..." }`
校验通过后重置密码并**返回新 token**（自动登录）。

### 1.7 `GET /api/v1/auth/captcha`（图形验证码）

无需认证，每次调用生成新的 4 位验证码（数字 + 去易混淆的大写字母），返回 PNG 图片的 base64 data-uri，
供前端 `<img :src="image">` 直接显示；点击图片重新调用本接口即可刷新。

**响应 `CaptchaResponse`**

```json
{
  "api_version": "1.0",
  "ok": true,
  "data": {
    "id": "d8eefc3e5a...",
    "image": "data:image/png;base64,iVBORw0KGgo...",
    "ttl": 180
  },
  "error": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 验证码唯一 ID，提交时作为 `captcha_id` |
| image | string | PNG 图片 base64 data-uri |
| ttl | int | 有效期秒数（默认 180，`KESE_CAPTCHA_TTL` 可调） |

- 校验只存**哈希**，常量时间比较；验证码**一次性使用**（校验成功即作废），过期或错误均返回 `CAPTCHA_INVALID`。
- 生成依赖 Pillow + TTF 字体（默认 DejaVuSans，Docker 镜像已内置 `fonts-dejavu-core`）；缺字体时回退 Pillow 内置字体，兼容任何环境。

```json
  "stock": 320,

  "shop_type": "官方旗舰店",
  "material": "高硼硅玻璃",

```

#### StandardEvidence（标准核验证据）

```json
{
  "raw": "GB 4806.5-2016",
  "normalized": "GB4806.5-2016",
  "matched": true,
  "status": "现行",
  "record": {
    "code": "GB 4806.5-2016",
```

| 接口 | 方法 | 认证 | 说明 |
| --- | --- | --- | --- |
| `/api/v1/data-source/sync` | POST | 需登录 | 从当前数据源（mock/jd）抓取 `keyword` 并写入商品表 |

**请求体**：`{ "keyword": "保鲜盒", "limit": 40 }`（`limit` 1~200，默认 40）

**响应 `SyncResponse`**

```json
{
  "api_version": "1.0",
  "ok": true,
  "data": {
    "source": "jd",
    "configuration": { "source": "jd", "configured": true, "cookie_loaded": false },
    "keyword": "保鲜盒",
    "fetched": 40,
    "skipped": 0,
    "elapsed_ms": 812,
    "messages": ["jd搜索 keyword='保鲜盒' 解析 40 条"],
    "product_total": 84
  },
  "error": null
}
```

| 字段 | 说明 |
| --- | --- |
| source | 实际使用的数据源：`mock` / `jd`（由 `KESE_PRODUCT_SOURCE` 决定） |
| configuration | 数据源状态；`jd.cookie_loaded` 表示是否配置了登录 cookie |
| fetched / skipped | 本次写入 / 被跳过的条数 |
| product_total | 同步后 `products` 表总数 |

- **mock**：按关键词从 `data/products.csv` 过滤写入（经统一适配层）；
- **jd**：实时抓取京东搜索页（纯 HTTP，匿名可试），按 `url`（含 sku）幂等 upsert，
  同 keyword 重复同步不会产生重复数据；
- jd 抓取失败 → 502 + `DATA_SOURCE_ERROR`（含风控/登录提示）。

**数据源开关**：`KESE_PRODUCT_SOURCE=mock|jd`（默认 mock）。`GET /api/v1/meta` 的 `data.data_source`
返回当前来源与配置状态，前端「数据源同步」页据此提示。

**真实性契约**：jd 搜索接口不含**执行标准号 / 材质 / 评分 / 库存**等字段，适配层如实留空、
由商品核验标记为「未标注」，**绝不编造**；补齐需接入 OCR（识别包装标准号）增量模块。

## 7. 安全措施（V5）

### 7.1 验证码发送限流

| 规则 | 阈值 | 超限响应 |
| --- | --- | --- |
| 同邮箱发码冷却 | 60 秒 | 429 `RATE_LIMITED` |
| 同邮箱每小时发码数 | 5 封 | 429 `RATE_LIMITED` |
| 每 IP 每小时发码数 | 30 次 | 429 `RATE_LIMITED` |

### 7.2 登录安全

| 规则 | 阈值 | 超限/触发响应 |
| --- | --- | --- |
| 连续失败锁定 | 5 次失败锁 15 分钟 | 423 `ACCOUNT_LOCKED`（对错密码均拒绝，成功后清零） |
| 每 IP 登录尝试 | 10 分钟 20 次 | 429 `RATE_LIMITED` |

### 7.3 接口 IP 限流

| 接口 | 规则 |
| --- | --- |
| 注册 | 每 IP 每小时 20 次 |
| 验证码校验 | 每 IP 每 10 分钟 30 次 |
| 重置密码 | 每 IP 每 10 分钟 30 次 |

### 7.4 其他

- **请求体大小限制**：默认 256KB，超出返回 413 `PAYLOAD_TOO_LARGE`。
- **安全响应头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
  `Referrer-Policy: strict-origin-when-cross-origin`、`X-XSS-Protection: 1; mode=block`。
- 限流响应携带 `Retry-After` 头；阈值均可通过环境变量 `KESE_*` 覆盖。

### 7.5 图形验证码

| 项 | 说明 |
| --- | --- |
| 接入点 | 注册、登录（固定入口防爆破） |
| 内容 | 4 位，数字 + 去易混淆的大写字母（`0/O/1/I` 已剔除） |
| 干扰 | 背景噪点 + 干扰线 + 字符随机旋转/颜色 + 轻微模糊 |
| 有效期 | 默认 180 秒（`KESE_CAPTCHA_TTL`） |
| 存储 | 仅存 `id → code 哈希 + expires_at`，一次性消费 |
| 校验 | 常量时间哈希比较，不区分大小写 |
| 失败语义 | 缺失 → 400 `CAPTCHA_REQUIRED`；错误/过期/已用 → 400 `CAPTCHA_INVALID` |

## 8. 兼容性约定

1. **字段命名**统一 snake_case，返回中文枚举值（现状/废止等）。
2. **金额**单位统一为「元」，浮点数保留 2 位小数；相似度/评分统一归一化为 0~100。
3. **null 语义**：`category=null` 表示全部、`brand=null` 表示不限、`budget_max=null` 表示不限上限。
4. 前端只依赖本契约中的字段，**不得**依赖后端实现细节（如表结构、排序算法内部值）。
5. 未来新增字段时只做**增量**，保持向后兼容。
