# 智能导购系统 · 模块详细设计

> 本文档描述每个模块的职责、输入输出、核心逻辑与扩展点。
> 与代码一一对应，便于答辩讲解与后续迭代。

---

## 目录结构总览

```
core/            基础层：配置、模型、文本解析
services/        业务层：标准核验、推荐编排、商品服务
algorithms/      算法层：相似度、评分
database/        数据层：SQLite 访问（用户 + 收藏/历史按用户隔离）
server/          HTTP 层：FastAPI 契约服务（schemas / app / service / security / main）
web/             前端：Vue 3 + Element Plus + ECharts（纯 HTTP 调用，含登录鉴权）
api_contract.py  契约组装（进程内与 HTTP 共用）
```

> **前端已由 Streamlit 更换为 Vue 3 + Element Plus**，通过 `web/src/api.js` 纯调用 FastAPI 契约服务；
> 后端业务层 `core/services/algorithms/database` 保持不变。旧的 `pages/`（Streamlit）已移除。

## 1. core/config.py —— 全局配置

**职责**：集中管理路径、评分权重、词表常量。

| 配置项 | 说明 |
| --- | --- |
| `SCORING_WEIGHTS` | 多因素加权权重（和必为 1.0），参见 §4 |
| `TOP_N` | 默认推荐数量 |
| `SALES_CAP` | 销量的归一化封顶值 |
| `SHOP_TRUST` | 店铺类型 → 信誉分映射 |
| `CATEGORIES / BRANDS / TAGS_VOCAB` | 类别、品牌、标签词表（供下拉框与自然语言解析共用） |

**扩展点**：调整权重、增加词表均在此处修改。

## 2. core/models.py —— 数据模型

| 模型 | 用途 |
| --- | --- |
| `Product` | 统一商品数据模型（贯穿全系统的标准结构），含名称/类别/品牌/价格/评分/销量/材质/执行标准/标签等 |
| `StandardRecord` | 标准知识库中的一条标准记录 |
| `StandardEvidence` | 对商品声明执行标准的核验证据（含匹配结果、状态、记录引用） |
| `RecommendQuery` | 推荐请求（类别/预算/偏好/品牌/是否仅现行标准） |
| `RecommendationItem` | 单条推荐结果（商品+得分+维度明细+理由+标准证据） |

`Product.from_row()` 负责把 SQLite 行转换为模型，是数据层与业务层的衔接点。

## 3. core/text_process.py —— 自然语言需求解析

**职责**：从自由文本抽取结构化需求。当前为「正则 + 词表匹配」轻量实现。

| 函数 | 说明 |
| --- | --- |
| `extract_budget` | 支持「300 以内」「100-300 元」「250 左右」等表达 |
| `extract_category / extract_brand / extract_tags` | 词表匹配抽取类别/品牌/标签 |
| `parse_requirement` | 集合以上函数，返回结构化 dict，供页面一键填充 |

**扩展点**：未来可替换为 LLM 结构化输出（PydanticAI），只需保持 `parse_requirement` 返回结构不变。

## 4. algorithms/similarity.py —— 相似度算法

**职责**：用 TF-IDF 把「商品文本」与「用户偏好」向量化，再计算余弦相似度。

- 商品文本 = `名称 + 类别 + 品牌 + 材质 + 标签`。
- 用户文本 = 用户选择的偏好标签。
- 用户未选任何偏好时返回中性值 0.5，避免偏向。

```python
matrix = TfidfVectorizer().fit_transform(corpus + [query])
similarity = cosine_similarity(matrix[-1], matrix[:-1])
```

## 5. algorithms/scoring.py —— 评分引擎

**职责**：把各维度得分归一化到 0~100，然后按权重加权求和。

### 综合评分公式

```
综合匹配度 = Σ (维度得分 × 权重)
```

| 维度 | 权重 | 计算方式 |
| --- | --- | --- |
| 相似度 | 30% | 余弦相似度 × 100 |
| 标准核验 | 20% | 现行=100 / 未收录=48 / 无法识别=30 / 未标注=15 / 废止=10 |
| 价格匹配 | 15% | 越接近预算中位数越高，越界按比例衰减 |
| 用户评分 | 12% | 5 分制 → ×20 |
| 销量 | 8% | 相对 5 万封顶归一化 |
| 品牌匹配 | 8% | 命中偏好 100，不限 60，未命中 40 |
| 店铺信誉 | 7% | 官方旗舰店 100 / 自营 92 / 专卖店 82 / 第三方 68 |

## 6. services/standard_service.py —— 执行标准核验（课设亮点）

**职责**：把商品声明的标准编号归一化后到本地知识库核验，返回核验结论。

### 归一化规则

`normalize_standard_code`：去空格、大写、统一「—/–/－」为 `-`。
例如 `GB/T 4806.7-2023` → `GB/T4806.7-2023`。

### 识别规则

`extract_standard_codes` 用正则从任意文本（如 OCR 结果）抽取 `GB / GB/T / QB / QB/T / SN / HG / JC` 类编号。

### 核验流程

```
商品声明编号 raw
   ↓ normalize
norm
   ↓ 是否以 GB/QB/SN/HG/JC 开头？
   ├─ 否 → 状态「无法识别」
   └─ 是 → StandardRegistry.lookup(norm)
            ├─ 精确命中 → 按记录 status（现行/废止）
            ├─ 无年份命中 → 归属该 base 最新的一条现行记录
            └─ 未命中 → 状态「未收录」
```

**关键设计**：`StandardRegistry` 按 `base（去年份编号）` 建立索引，商品只写 `GB4806.7`（无年份）也能归属到最新现行记录。

### OCR 接入预留

未来把包装图片经 OCR 得到的文本传入 `verify_standard` 即可，本模块零改动。评分映射 `standard_score` 直接作为推荐维度之一。

## 7. services/recommendation_service.py —— 推荐编排

**职责**：协调完整推荐链路。

```
products ──filter_products──► 硬条件过滤（类别/预算/有货）
        ──compute_similarity──► 相似度
        ──verify_standard──►（逐商品）标准核验
        ──compute_score──►（逐商品）加权评分
        ──_build_reasons──► 可解释推荐理由
        ──sort──► Top-N
```

- `require_standard=True` 时，仅保留核验状态为「现行」的商品。
- `recommend_from_records` 供以字典入参的调用方（未来 API）复用。

## 8. services/product_service.py —— 商品服务

封装商品列表查询、类别枚举、单商品查询与收藏行为。

## 9. database/db.py —— 数据访问层

**职责**：SQLite 建表、种子导入、CRUD、用户、历史与收藏持久化。

### 表结构

| 表 | 字段要点 |
| --- | --- |
| `products` | 名称/类别/品牌/价格/评分/销量/库存/店铺/店铺类型/材质/标准编号/标签/描述/来源/链接/图片/创建时间 |
| `users` | 用户名（唯一）、密码哈希、创建时间 |
| `recommendation_history` | 用户 ID、查询 JSON、结果 JSON、创建时间 |
| `browse_history` | 用户 ID、商品 ID、创建时间 |
| `favorites` | 用户 ID、商品 ID（联合唯一）、创建时间 |

`seed_from_csv` 从 `data/products.csv` 全量重建商品表；`init_db` 建表并自动执行迁移（老库补充 user_id 列，幂等）。
收藏、历史、浏览均按 `user_id` 隔离。

## 9.5 server/security.py —— 认证安全

| 能力 | 实现 |
| --- | --- |
| 密码哈希 | `hashlib.pbkdf2_hmac('sha256', ..., 200_000)`，盐随机，存储格式 `salt$iters$digest` |
| 密码校验 | 常量时间比较 `secrets.compare_digest` |
| 令牌签发 | PyJWT HS256，payload 含 `sub/username/iat/exp`，默认 7 天过期 |
| 令牌校验 | `decode_access_token` 返回 payload 或 None |
| 密钥来源 | 环境变量 `KESE_JWT_SECRET`；未设置则生成进程内临时密钥 |

## 10. api_contract.py —— 前后端契约实现

提供 `build_recommendation_response(items, query)`，把推荐结果组装为统一的 JSON 结构（见《前后端契约》文档），

## 11. server/ —— FastAPI 契约层（HTTP 实现）

| 文件 | 职责 |
| --- | --- |
| `schemas.py` | Pydantic v2 契约模型（请求/响应/数据结构/统一错误/认证） |
| `app.py` | 路由、CORS、启动建库、统一异常处理、JWT 依赖与路由守卫 |
| `service.py` | HTTP 参数 ↔ 核心模型转换，复用业务层；按用户持久化历史 |

| `main.py` | `python -m server.main` 启动入口 |

新增端点：`/api/v1/health`、`/api/v1/meta`（前端表单词表）、`/api/v1/parse`（自然语言解析）。
