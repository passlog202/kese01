# 技术优化点调研报告

> 日期：2026-09-23　目的：针对项目现有技术栈，评估有哪些**真实验证过的**优化空间，供决策。
> 方法：全部方案都在本机用真实数据跑过对比，结论可复现。

## 一、核心发现（已实测）

### 1. 中文相似度：TF-IDF 缺分词是最大缺陷，且有零依赖解法

**现状**：`algorithms/similarity.py` 用 `TfidfVectorizer(token_pattern=word)`，
但中文无空格，导致「乐扣乐扣耐热玻璃保鲜盒630ml」被当成**一个长 token**，
且「耐高温」≠「耐热」字面匹配不上。

**实测对比**（用户搜「耐高温 玻璃 保鲜盒」，A=耐热玻璃保鲜盒最该命中，B=塑料保鲜盒应垫底）：

| 方案 | A | B(塑料) | C(玻璃碗) | D(玻璃杯) | 依赖 |
| --- | --- | --- | --- | --- | --- |
| 现状 word | 0.193 | 0.000 | 0.000 | 0.000 | 无 |
| jieba `cut_for_search` | 0.482 | 0.265 | 0.082 | 0.087 | +jieba |
| jieba 精确模式 | 0.444 | 0.178 | 0.000 | 0.171 | +jieba |
| **char n-gram (2,3)** | **0.229** | **0.081** | **0.072** | **0.073** | **零依赖** |

**评估**：
- **jieba `cut_for_search`** 分数最优（召回最全），且支持自定义词典
  （可把「保鲜盒/保温杯/食品级」等词表加入，效果还能再提升）；缺点是 pip 安装
  走 legacy setup.py（有 DEPRECATION 警告，但功能稳定、纯 Python、体积小）。
- **char n-gram `analyzer="char", ngram_range=(2,3)`** 是 sklearn 原生参数，
  **零新依赖**，区分度最好（A 最高、B 最低），成本最低、最稳。
- **推荐**：词表规模小、追求零依赖 → char(2,3)；追求效果上限 → jieba+自定义词典。
  二者都远优于现状。

### 2. 需求解析（text_process.py）两处小 bug

实测 `parse_requirement`：
- `'大概50左右'` → 算出 `57.499999...`（浮点误差未 round）
- 正则 `_PRICE_UNDER` 会把「保温」的「温」等无关场景误判概率低，但**价格中位数 85%~115% 的
  区间倍率是拍脑袋定的**，没有依据。

**优化**：结果统一 `round(2)`；区间倍率抽到 `core/config.py` 常量，便于调参。

### 3. 评分引擎（scoring.py）权重合理性

- 权重硬编码在 `core/config.py` 且有 `assert 合计=1.0` 保护，架构没问题。
- 可优化：`score_sales` 用固定 `SALES_CAP=50_000`，但真实数据（京东）销量是「已拼万件」量级、
  mock 是几千~2 万量级，**跨数据源不可比**，可按数据源分位数归一化。
- `score_rating`：真实数据无评分字段（恒 0）→ 该维度对真实商品恒 0 分，标准核验/销量/评分
  三个维度对真实数据都会失真。**需按「字段是否可信」动态调整权重**。

## 二、真实数据源配套（上一轮遗留）

- 京东/1688 拉到真实商品后 `price=0 / rating=0 / sales=0` 的商品会污染推荐排序
  （拿 0 分但照样进 Top-N）。同步时应过滤**无价/无标题**商品，或标记「数据不全」降权。
- 执行标准号 OCR 仍是空位：真实商品标准核验恒为「未标注」，20% 权重形同虚设。
  轻量替代：按「标题关键词 → 标准号规则」先做一层推测（如 316 不锈钢 → GB 4806.9）。

## 四、不在本轮考虑（说明理由）

| 项 | 理由 |
| --- | --- |
| BERT/句向量模型 | 需 torch + 下载模型，课设 Mock 场景过重，答辩解释成本高 |
| HanLP/LAC/pkuseg | pkuseg 包大、LAC 需 paddle、HanLP 资源重；小词表场景 jieba/char 足够 |
| 向量数据库 (chroma/milvus) | 44 条商品全量 TF-IDF 内存计算即可，引入 DB 是过度设计 |
| Redis 限流 | 现 SQLite 固定窗口限流对课设足够，空转没必要 |

## 五、建议实施顺序

1. **相似度 char(2,3) 或 jieba**（A 级，成本最小、提升最明显）
2. **需求解析浮点/常量修复**（A 级，几行）
3. **真实数据清洗 + 评分字段可信度**（B 级）
4. 体验/交付类（C 级）
